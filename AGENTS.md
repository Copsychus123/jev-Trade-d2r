# Repository Guidelines

## Project Overview
Jev Ultrafast is a small browser Agent. It takes one natural-language goal, observes the page as indexed elements, asks TypeSafe (a remote chooser) for an operation plus a target, and executes it through Chrome DevTools Protocol. The shipped use case is Traderie Diablo II: Resurrected: search an item, open its product page, read the Trading (目前掛單) listings, click the Recent Trades (近期成交) tab, read the trades, and show both as tables in a local web demo.

Read `README.md` (Traditional Chinese) and `docs/design.md` before editing. The user is non-technical and writes in Traditional Chinese: explain results in plain Traditional Chinese, without jargon.

## Hard Rules
- Keep the loop small: page -> indexed elements -> operation + target -> execution.
- The input is one natural-language goal. No site-specific plans and no hardcoded field values or click targets. The model never emits selectors or executable code.
- TypeSafe chooses an operation and operation-specific target heads in one request. Consume only the selected operation's target. Targets must map to observed elements and supported operations.
- `TYPE_TEXT` types the text the caller supplied to `Agent(text=...)`; no model generates field text.
- Current stage scope: search -> product page -> read all Trading listings -> click Recent Trades -> read all trades -> show both as tables. Data analysis modules were retired. The only model that may choose browser actions is Jev (TypeSafe), with one mechanical exception: `Agent(finish_phase_after=(label, n))` (`site.phase_finish_rule`) ends a phase without asking Jev once the action named `label` (Load More) ran `n` times in that phase; it is logged in `state["rule_events"]` and shown in the decision log. The same rule also runs the loading cycle inside a phase (`Agent._next_by_rule`): after Load More it scrolls to the bottom, after scrolling to the bottom it presses Load More if that button is on the page; otherwise (first step of a phase, no button) Jev chooses. Rule steps have `model_calls = 0` and appear in `rule_events` with `press: True`. Apart from the table jump and the base rule (`stripToBase`) below, rules never choose search, product or tab targets; do not add any other LLM call, in particular no LLM-based data analysis and no model that generates field text.
- Finding the product (extension, `extension/src/traderie/finder.js`) has three layers, one attempt each: (1) table jump: the English name is in `extension/src/traderie/data/items.json` -> the program opens `/product/<slug>` itself, with no Jev call, then checks the page title is that item (otherwise layer 2); this is the only place the program chooses a product, and it never chooses anything else; (2) search: Jev types the name that the program supplies and picks the result; the program cleans the text first and never lets Jev rewrite it; (3) base list: only when the search page says "No results could be found" for a well-formed name, the plain item type comes from the fixed `bases` list (program rule first, see the next bullet, otherwise Jev picks one or none through `pick_base`, `POST /api/run/base`), then one more search with that name; no pick means "not found" and the run ends. The base list is a fixed option list; it never filters the page's element list. The result page always says which layer found the item, and a base result says the quality was not filtered. Chinese names are translated through the same table (`zh`); a Chinese name that is not in it fails before the quota is used. Names shared by two products (`Crescent Moon`, `Ward`, `Wirt's Leg`: `ALLOWED_DUPLICATE_KEYS` in `scripts/audit_item_tables.py`) are ambiguous: no table jump, search decides.
- Program-side base rule (sanctioned exception, `stripToBase` in `extension/src/traderie/lookup.js`; mirrors the table jump): in layer 3 the program first drops leading quality words one at a time ("Rare Ring" -> "Ring") and takes the first remainder that is an exact entry of the fixed `bases` list. A match is sent as `base` to `POST /api/run/base`, which only checks it against the server's list and swaps the run token: no Jev call. Only when nothing matches does Jev pick from the list (`pick_base`: one request, split into several questions when the list is long). The rule chooses search text from a fixed list, never an element or a click, and does not filter the element list. Model calls per lookup: table jump 0; search = the Jev calls of the Agent loop (`choose` may re-ask once, both requests count in `usage`); base layer 0 (rule matched) or 1 (`pick_base`). All of them share one budget of 30 Jev calls per run (`JEV_CALL_LIMIT` in `extension/src/agent.js`, `MAX_MODEL_CALLS` in `services/jevsvc/app.py`); the core demo has its own limits (60 actions, 120 decisions, `docs/design.md` Budgets).
- Stale-retry bound (extension, `extension/src/agent.js`): `STALE_RETRY_LIMIT = 3` — three consecutive `StalePage` failures on the same target (`choice`) on the same page fingerprint end the run as `blocked` with a Traditional-Chinese `scope_blocked_reason` (`連續 N 次都無法操作「<label>」（畫面沒有變化），查詢已停止`), a `rule_events` entry carrying `stale: true` and the count, and a matching `stale_events` line; any real change (a new page fingerprint, or a different target) resets the streak. When `Tab.overlayCover` (`src/jev_ultrafast/covered_overlay.js`, a read-only structural measurement: the failed target's centre is covered and the covering element's nearest positioned ancestor is `position: fixed` and covers at least 90% of the viewport) says a pop-up covers the target, the reason is instead the actionable 「有彈出視窗蓋住頁面…」 message; the measurement failing, or finding nothing, keeps the message above, and it never clicks or names a site element. It must stay: the click never executes, so no `history` entry is pushed, `MAX_STEPS` (which reads `history.length`) can never fire and `_finishPhaseByRule` counts only executed presses, so the mechanical loading rule could retry a covered element forever (measurements in `docs/design.md`). Related: `state.attempts` counts every action attempt (executed or stale) and `_prepareAction`'s bound is `history.length >= MAX_STEPS || attempts > MAX_STEPS` — keep both halves, or a covered element stops counting toward the step budget again.
- Challenge-guard precision (extension, `extension/src/traderie/site.js`): the bare word "captcha" counts as a challenge only when the page text is under `CHALLENGE_TEXT_MAX` and contains none of `TRADING_MARKERS` ("Trading For" / "Make an Offer", defined in `site.js`); the explicit signals ("just a moment" in the title, "verify you are human") and the `CHALLENGE_FRAMES` probe are unchanged. It must stay because the extension's `page.text` is snapshot text over the visible viewport only: a normal logged-in product page (measured 1998 chars) contains Traderie's own changelog line "Fixed captcha bugs when going between games", and the old word test made `sidepanel.js`'s `judge()` show 「Traderie 要求驗證或登入…防護頁/驗證碼」 instead of the run's real stop reason. The Python twin (`src/jev_ultrafast/traderie/site.py`) needs no guard: its text is the whole-page `innerText`.
- Item tables (`items.json`) are a snapshot: regenerate with `uv run --group e2e python scripts/build_item_tables.py` (Windows only; starts the dedicated Chrome headless; Traderie blocks plain downloads). It builds `artifacts/item_tables_candidate.json` first and replaces the committed table, atomically, only if no category vanished or shrank by more than 10% (`--force` skips only that check) and `scripts/audit_item_tables.py` finds no problem (required categories and minimum counts, unique normalized names except the allow-list, slug format, base list, coverage floors, noise). `generated_at` only changes when the content changes. `--from-cache` rebuilds from `scripts/data/item_pairs.json` (commit it after a full run if it stays under about 300 KB; larger snapshots go to the git-ignored `artifacts/item_pairs.json`) without opening any website. The settings screen shows the table age (`tableAge`, stale after 90 days) and a table-jump miss note carries the running miss count; a stale table only loses the shortcut.
- Second search, yellow/blue/white items (extension, `extension/src/traderie/stats_flow.js`, `stats.js`, `properties.js`; form in `stats-form.js`; panel flow in `stats-query.js`): items without a fixed name are found by their affixes on the D2R home page ("Search All Stats"). This is a third program-side navigation, after the table jump and `stripToBase`: the conditions the player switched on and confirmed in the form become the home page address (`?prop_<id>Min/Max=…`, `prop_Rarity=…`, `tags[]=…`), which the program opens and reads (first page only). No Jev, no backend, no quota. Property ids and names are never written in code: they are read from Traderie's own property list from inside the player's Traderie tab (`GET /api/diablo2resurrected/properties?global=true`, kept in `chrome.storage.local` for 7 days; a failed read is an error, an old copy is never a fallback). A condition with no, or more than one, matching property ends the query before anything is searched. Values that reach the address are checked to be digits. Affix lines of a screenshot are read by rules (`ocr/affixes.js`, dictionary `ocr/affix_dictionary.js`), never by a model, and only fill the form: a query never starts from a screenshot, the reader ticks the attributes it recognised and fills in the numbers it read, each marked in the form as coming from the capture for the player to confirm or edit (the reader misreads numbers, so the mark is the point; the player still presses start), and a ticked non-bool condition must carry at least one value (0 counts) before the search starts, while a bool condition needs none and ticking nothing at all stays legal. The base stays required, but the field offers the shipped item types as suggestions (`lookup.baseOptions` over `items.json`'s `bases`, filled when 模糊搜尋 mode is chosen; a suggestion, never a restriction), because a unique item's tooltip never names its base. The results line leads with what the rows it read are asking (min/median/quartiles of the High Rune Value, `traderie/price-summary.js`; unpriced rows are counted, never guessed) and then names where the query's input came from, typed or a picture or a scan record (`labels.sourceLine`, `panel-state.js`). Measured: this path has **no realised prices** — the affix filter URL has no recent-trades view (the filtered home page's 1037 links reach none of them and it carries only listing markers; the product page's `/recent` suffix on that URL lands on HELP with nothing in it), and trades exist only on a product page; see `docs/design.md`. The result is checked independently (`verifyStats`: home page, `filters_in_url`, `filters_shown`, `rows_match_filters`, rows read). `rows_match_filters` needs every listing to carry a card line for each number condition: each listing keeps its affix lines in `affixes` (`parseTradingTxt`; environment tags, quality words, `Classic` and variant words are dropped; `CARD_TAGS` is the same list in `parsing.js` and `parsing.py`), and `conditionPattern` in `stats.js` turns the property name into the line it prints (`+{{value}}% Faster Cast Rate` -> `+8% Faster Cast Rate`). It runs on the rows the player sees (after the base display filter). Measured: Traderie did filter the list for unreachable numbers (life >= 99999 listed only charms whose life line is a joined range), so this is a guard against a page that lists everything, not a repair of a seen failure. The element list is not filtered by site vocabulary. `scripts/probe_stats.py` (read-only, needs the dedicated Chrome's Traderie login) re-measures the facts this relies on (list reachable, "and" between conditions, `Rarity` values, `tags[]`); its findings are in `docs/design.md`.
- Screenshot reader (extension, `extension/src/ocr/`): PP-OCRv6 small (Apache-2.0) runs in a side-panel module Web Worker through onnxruntime-web 1.30.0 (MIT); one engine only — WebGPU when `navigator.gpu` returns an adapter, otherwise wasm fixed at one thread. Only `ort.min.mjs`, the `ort-wasm-simd-threaded.jsep.mjs`/`.wasm` pair, `LICENSE` and `VERSIONS.json` ship in `extension/src/vendor/ort/`; `extension/src/vendor/ort/VERSIONS.json` records the pinned tarball and the size and SHA-256 of every vendored file, and `extension/test/ocr-vendor.test.mjs` recomputes them, so update both together and keep `.gitattributes` (`-text` for the vendor folder) so line endings never change the bytes. `manifest.json`'s CSP allows `'wasm-unsafe-eval'` (never `unsafe-eval`) and the host `https://www.modelscope.cn/*`; against the previous revision the only change is that host. Models are NOT shipped: the first time a panel needs them, `models.js` downloads the four pinned files from modelscope (`RapidAI/RapidOCR` v3.9.2: the det/rec ONNX, the v4 cls ONNX and `ppocrv6_dict.txt`), checks size and SHA-256, and stores them in IndexedDB (`keyval-store`, `jev/ppocr/<name>` bytes and `jev/ppocr/<name>.sha256`); 下載期間顯示非阻擋通知、進度條與「取消下載」鈕，不再詢問，沒有玩家動作也會下載；the bytes are handed straight to `ort.InferenceSession.create`, so nothing is fetched at run time. No automatic retry. A download can be cancelled (button, closing or replacing the picture), gives up after 30 s without data, and stops as soon as more bytes than the model has arrive; whether a model is stored is decided from its small version record and the key of the bytes (the bytes are never read for that). If the engine cannot start, the stored records are dropped and the next read offers the download again. The worker is created once and terminated after about 60 s without a read (`createEngineCache` in `engine.js`). On panel start `forgetLegacyTesseractModels` deletes the 16 old Tesseract keys once. The det/cls/rec pipeline is `extension/src/ocr/ppocrlib.js`, ported from the git-ignored spike (one local edit: the shared `padCrop` that `classify` and `recognize` both batch with). Name matching only knows English and Traditional Chinese names, so other languages show the read text and need a typed name. Matching (`match.js`) never uses stat lines, ignores short English words, and tolerates fewer wrong characters in short Chinese names; the best result is only written into the item-name field (other candidates swap it) and a query never starts from a screenshot: the player presses 開始查詢. The entrance is the 📷 button beside the item-name field (paste/drop anywhere in that card also works); the reading panel only exists while a picture is loaded. Measure with `uv run --group e2e python scripts/ocr_e2e.py` (Windows only; truth list `scripts/data/ocr_truth.json` plus the held-out list `scripts/data/ocr_truth_holdout.json`, scored in the same run beside it; each group fails when its accuracy falls below the same group of the last accepted `artifacts/ocr-e2e/report.json`, or, for the tuned group without one, below the measured floors in `FALLBACK_FLOORS`; the held-out group's floor is set by its first accepted run). The PP-OCRv6 engine comparison and browser spike are recorded in `docs/design.md`.
- Gear scan, a third navigation beside the name search and the affix search (extension, `extension/src/scan/`): for an online character whose equipment is in no local save, the player shares the D2R window once through Chrome's own dialog and hovers each item; the program never moves the mouse, sends no input to the game and has no global hotkey — it only reads the shared picture. `capture.js` takes frames with `getDisplayMedia` + `MediaStreamTrackProcessor` (never `requestVideoFrameCallback` or a timer, which stop or throttle while the game covers Chrome); they are shrunk to `DETECT_WIDTH = 480` and a pure module finds the tooltip (`tooltip.js`): dark-pixel rows seed a band and a row or column inside it belongs to the panel through an inside-density window (a longest-run rule fails because the antialiasing on a text line breaks a row into 12..37 px pieces against the 48 px minimum), then `boxKey`'s content identity — the panel's own top square, 8×8 mean-grey cells quantised into 6 grey levels, matched within 12.5 % of the cells (measured: the same panel differs in 0..2 of the 64 cells, two different panels in 24..45) — makes the same panel shown again one crop. `session.js` is the state machine: one crop per held tooltip, one record per item (完全相同的兩件只記一筆), the list is memory-only and disappears with the side panel, 清除紀錄 clears it, and CSV export works without ever running a query. Each record's 精準搜尋 and 模糊搜尋 buttons only prefill the form (`onSearchName`/`onSearchStats`) and never start a query; 模糊搜尋 ticks the affixes and prefills the base from the **base candidate of the same read** (`scan/session.js` `baseCandidate`, the first `kind === "base"` of the candidates the matcher already returned), or from the record's own name when the record was a base, always marked as coming from the capture; a query that came from a record and ended in a problem offers 用詞綴找同類, which re-enters the affix search with that record (`panel-state.js` `affixHandoff`). the screen downloads what is missing by itself, showing a non-blocking notice with a progress bar and a 取消下載 button (`#scan-download`), and the models, engine cache and matcher are the screenshot reader's own (`extension/src/ocr/panel.js`), one engine and one download path. Honest limitation: with the tooltip at its native pixel size on a 1080p/1440p capture (a UI that does not scale with resolution) no signal is left at `DETECT_WIDTH = 480`; the lever would be raising that width.
- Never retry a browser mutation. Log execution before observing its result.
- Keep credentials server-side and `.env` ignored. Tests must not call paid APIs.
- Verify actual final outcomes independently. A `DONE` choice is not proof of success.
- Keep examples, README claims, raw evidence and model-call counts consistent.
- Do not commit or push unless the user asks. Many files in the working tree are modified or deleted by earlier tools; leave them alone.
- Untracked analysis files left by earlier tools are not authoritative (for example `SMOKE_TEST_UPGRADE_REPORT.md` falsely claimed "13/13 通過"). There is no `archive/` directory any more: that sort of one-off output lives under the git-ignored `artifacts/` (the raw evidence `docs/design.md` cites sits in `artifacts/ocr-bench/` and `artifacts/ocr-spike/`, and `artifacts/probe/` is written by `scripts/probe_stats.py`), so nothing under `artifacts/` is a source of truth unless `docs/design.md` cites it.

## Architecture & Data Flow
```
goal -> demo.py (HTTP, loopback) -> Agent.command(tick = predict + act)
          predict: Browser.observe -> model.choose (TypeSafe) -> decision
          act:     Browser.act (CDP input) -> Browser.observe -> history
        traderie/controller.advance() reads each view when the Agent finishes it
```
- `src/jev_ultrafast/agent.py`: `Agent` is the only owner of `agent.state`. Commands: `predict`, `act`, `tick`, `handoff`. Status values: `ready`, `predicted`, `handoff`, `done`, `blocked`. A single-string goal on a Traderie D2R URL becomes a 2-phase plan (`trading`, `recent_trades`); finishing phase A sets `awaiting_handoff` and the controller must call `handoff`.
- `src/jev_ultrafast/browser.py`: one CDP session through `browser_harness`. `observe`, `fresh`, `act`, `evaluate`, `navigate`, `settle`, `close`. `fingerprint()` hashes url, text, actions and scroll. After a click, `observe` waits until the visible text has changed once (or 1.0 s passed) and then stayed unchanged for 0.4 s (cap 6 s; measured: 0.7/1.5 s gave a median loop of 26 s, 0.4/1.0 s about 16 s); `wait` sleeps 4 s so slow XHR content can arrive (a shorter wait made Jev answer `blocked` on half-loaded search results).
- `src/jev_ultrafast/snapshot.js`: runs inside the page. Garbage accessible names (`[object Object]`, `undefined`, `null`, `NaN`) are ignored and the visible text is used instead (Traderie ships `aria-label="[object Object]"` on listing links). Lists up to 250 visible safe elements as `e1..eN`, plus controls `scroll_down`, `scroll_up`, `scroll_bottom`, `scroll_top`, `wait`. Page text is capped at 6000 chars and only covers the visible viewport.
- Phases: `Agent.state["phase_start"]` is where the current phase began in `history`; `choose` receives only that part, so `recent_actions` and `action_counts` (how often each action ran in this phase) restart at the handoff. The goal tells Jev to choose DONE when `action_counts` shows Load More at `LOAD_MORE_LIMIT` (counting from a list of actions was unreliable). Views carry `has_more` (a Load More button still on the page when it was read).
- `model.choose` asks Jev again, once, without the chosen operation when its target probability is below `MIN_TARGET_PROBABILITY = 0.5` (four same-name links once sent the Agent to another product page at 26%); the decision then has `reasked` and `model_calls = 2` and the usage sums both requests. `action_space` keeps at most `MAX_SAME_NAME_ELEMENTS = 2` elements with the same name and role (26 Min/Max boxes cost about 8% of the tokens). The Load More count (0-5, `site.validate_load_more`) comes from the demo selector (`reset` body `load_more`) or `--load-more`.
- `src/jev_ultrafast/model.py`: `post_json` (retries only network errors and HTTP 429/503/529), `action_space`, `choose`, `validate_choice` (checks probabilities only; there is no confidence anywhere). `questions.py` holds the prompt strings.
- `src/jev_ultrafast/config.py`: constants (`MAX_STEPS = 60`, viewport size), frozen `Settings` from `get_settings()`, `load_dotenv` (uses `setdefault`: the real environment wins over `.env`).
- `src/jev_ultrafast/demo.py`: loopback inspector on `127.0.0.1:8766`. POST checks Host, `X-Demo-Token` and Origin (403), single busy lock (409), `ValueError/RuntimeError/TimeoutError` -> 400. Commands: `reset`, `tick`, `report`; the page has one start button (「開始查詢」, runs `tick` until done), a stop button and the report button. `GET /api/report` returns the markdown; `GET /api/raw?view=trading|recent_trades` returns the stored page text (state carries only `text_length`; decisions other than the last are trimmed to a summary). Demo-owned fields live in `RUN` (`item_name`, `market`, `report_md`); never mutate `AGENT.state` from the demo.
- `src/jev_ultrafast/traderie/`: the Traderie domain.
  - `site.py`: URLs, `build_goal`, `LOAD_MORE_LIMIT = 2`, `product_root_url`, `traderie_scope_reason`, `detect_guard`.
  - `controller.py`: `new_market`, `read_view`, `verify_views`, `advance`, `run_agent`, `save_report`. Each view is read once, from the page the Agent is on (no navigation, no retry), into rows via `parsing.parse_trading_txt` / `parse_recent_trades`, and cross-checked against the page text ("Trading For" / "They Give" counts). Status per view: `NOT_RUN`, `PASSED`, `FAILED`, `BLOCKED`.
  - `verification.py`: `read_settled_page`, `matches_item`. The 8 independent checks live in `controller.verify_views`: `product_page`, `item_match`, `same_product`, `trading_view`, `recent_view`, `trading_rows_ok`, `recent_rows_ok`, `not_blocked`.
  - `parsing.py`: rule-based readers, no AI.
  - Retired analysis code, helper scripts and the old OCR project are no longer in the tree.
- `src/jev_ultrafast/static/`: `index.html` (token placeholder `__TOKEN__`), `app.js`, `style.css`, `csv.js` (CSV export, no DOM access, tested through node), `tokens.css` (the shared colour vocabulary: the names and the panel's values; `extension/build.py` copies it next to `sidepanel.css`, which uses it, while the demo still declares its own palette in `style.css` - `tests/test_ui_tokens.py` keeps that honest). Results are two columns (listings 3fr, trades 2fr) at >= 1000px, stacked below; `marketViews.trading.mergeInto` shows the high-rune column as small text under the price only in the wide layout (CSS `.col-merge`/`.inline-extra`), CSV still exports all columns. Three tab panels: `tab-run`, `tab-results`, `tab-usage` (all element ids must stay in `index.html`; `tests/test_ui_static.py` checks this). The page switches to the results tab once when `market.verification` appears, unless the user picked a tab. It shows the same table columns as the panel and the same sentences for a failed check, each a copy the page carries because the two cannot share code, kept in step by `extension/test/columns-parity.test.mjs` and `extension/test/check-reasons-parity.test.mjs` (a failed run must never print an identifier like `same_product` to a non-technical player). Page text is untrusted: write table cells with `textContent`, never `innerHTML`; CSV cells starting with `= + - @` get a leading apostrophe.

## Key Directories
- `src/jev_ultrafast/`: package. `traderie/`: domain code. `static/`: demo UI. The extension and backend builds copy the page scripts and the model code from here.
- `scripts/`: `traderie.py` (CLI, same flow as the demo).
- `scripts/` (more): `login.py` (visible dedicated Chrome for the one-time Traderie login), `check_guards.py` (live browser guard checks; collects failures and raises one `AssertionError`), `_cdp.py` (the small CDP client the Chrome scripts share), `stub_backend.py` (the zero-quota `--stub-chooser` backend: the real routes with a stub chooser behind `/api/choose`, served through `services/dev_server.make_server`), the Chrome end-to-end checks (`extension_e2e.py`, `extension_batch.py`, `ocr_e2e.py`; Windows only, real Chrome and real quota: `uv run --group e2e python scripts/<name>.py`; `demo_e2e.py` needs no quota and no login - it renders the demo page from a throwaway server answering `/api/state` with the shape `demo.response_state()` really produces (a stubbed agent) in the dedicated Chrome the demo itself uses, and asserts the two tables, the merged high-rune column, the environment join, the text-only rendering of a `|`/newline seller name, the auto-switch to 查詢結果 and the 通過檢查 line; `extension_batch.py` needs `--yes`, reads its invite codes from `JEV_INVITE`/`JEV_TINY_INVITE` and does not rerun failures unless `--rerun-failed N`) and the table tools (`build_item_tables.py`, `audit_item_tables.py`). Product code lives in `src/` (the `jev_ultrafast` package: agent, browser, model, Traderie rules, page scripts), `services/` (backend) and `extension/` (Chrome extension). The e2e scripts build the extension into the git-ignored `extension/dist-e2e`, never `extension/dist`. `scripts/extension_e2e.py` leaves evidence while a run is in progress: the local backend's stdout is mirrored to the git-ignored `artifacts/perf/backend-<timestamp>.log` (one `choose … calls=… in=… out=…` line per answered Jev step; the path is printed at the end), each changed 3 s sample prints a progress line (the panel's step counter and its last 4 decisions), a failed sample is counted and reported (`取樣：成功 N 次、失敗 M 次`), and `--timeout` (default 300) bounds the run.
- `tests/`: pytest suite (`pyproject.toml` `testpaths`). `artifacts/traderie/latest/`: run output (`market.json`, `market_report.md`, `verification.json`; ignored by git). `artifacts/perf/` holds per-stage run timings (`run-<timestamp>.json` and the mirrored backend log `backend-<timestamp>.log`; git-ignored with the other artifacts), and the timing instrumentation (`extension/src/timeline.js`, `__jevLastRun`) is measurement-only. `.agents/skills/`: assistant skills, not product code.

- Module index (the files the rules above do not name; one line each, from their own headers): `extension/src/api.js` (backend calls; the base URL is passed in, never read from `config.js` here), `background.js` (the toolbar icon opens the side panel), `cdp.js` (the CDP port of `src/jev_ultrafast/browser.py`: `chrome.*` is only touched inside functions, never at import time), `dom.js` (the two DOM helpers every panel module shares: `$` for `getElementById` and `element` for a one-line `createElement`; ## Code Conventions & Common Patterns
- Python >= 3.12, ruff line length 120, rules `E,F,I`. Clean cutover: when removing a behavior, migrate every caller and delete dead code; no shims or aliases.
- Safety patterns to keep:
  - `Agent` consumes a decision once, before any mutation or model call.
  - `StalePage` triggers a re-observe and a new decision, never a replay of the action.
  - `Browser.fresh(page, action)` guards element actions (including `fill`); page-level `MARKER` is used for page-level actions.
  - Scope guard (`traderie_scope_reason`) blocks anything outside Traderie D2R.
  - Verification results always carry a human-readable reason (`view_reasons`, `failed_checks`).
- Errors: raise `ValueError` for caller mistakes, `RuntimeError`/`TimeoutError` for browser or network problems; the demo maps them to HTTP 400.
- Config: read through `get_settings()`; never read secrets in the frontend.
- Naming: snake_case modules and functions; test functions are full sentences (`test_stale_decision_is_consumed_before_any_mutation`); status strings are upper-case constants (`PASSED`, `BLOCKED`).
- Do not add keyword lists that filter the element list by site vocabulary; that hid the real search-result link once. Improve generic observation or prompts instead.

## Runtime/Tooling Preferences
- Python with `uv` (lock file `uv.lock`; dependency groups `dev` and `e2e`); `node` for `node --check` on the demo scripts and `node --test` for the extension tests. No CI directory.
- By default `src/jev_ultrafast/chrome.py` starts a dedicated headless Chrome (port 9355, profile `src/.tmp-jev-chrome` next to the package, git-ignored) and points `browser_harness` at it with a per-process daemon name (`BU_NAME=jev-<pid>`). `JEV_CHROME` selects the mode: `headless` (default), `window` (visible dedicated Chrome), `existing` (the user's own Chrome; needs remote debugging on port 9222, and if Chrome asks "Allow remote debugging?", only the user can click Allow).
- Only in the dedicated Chrome: advertising/tracker hosts are blocked (`BLOCKED_HOSTS`, halves memory), picture URLs are blocked when screenshots are off (`Browser(images=False)`; the demo keeps pictures for its screenshot panel), the page cache is capped at 50 MB, small caches are removed on close (the login stays), and renderer processes are limited. In headless Chrome the tab must be a foreground tab or screenshots hang.
- TypeSafe requires `TYPESAFE_API_KEY`. No local text model is needed.
- Without a login, Traderie hides Load More and may block Recent Trades. Tell the user to run `uv run python scripts/login.py`: the window now stays open until the login is actually detected (it polls `LOGGED_IN_JS`: host `traderie.com` and `readyState === "complete"` and a non-empty body and no `Log In` link left), pressing Enter only ends the wait early and the wait no longer depends on it, `JEV_LOGIN_WAIT_SECONDS` (default 600) bounds it, and reaching the bound prints a clear Traditional-Chinese message and exits 1; the old bare `input()` ended instantly on a stdin that cannot wait (EOF or redirected) and the window closed before the human could log in. In `existing` mode, log in in the user's Chrome instead.

The Chrome check is `scripts/scan_e2e.py` (`uv run --group e2e python scripts/scan_e2e.py`, Windows only) against the stand-in page `scripts/data/scan_sim.html`: it uses no Jev quota, and like every Chrome end-to-end script it must run while no other member of that family is running.
- Offline tests stub `browser_harness` before importing the package (see `tests/_harness_stub.py`: fake `browser_harness`, `.admin`, `.helpers` in `sys.modules`, then `# noqa: E402` imports). Mock with `monkeypatch`; use fake browser classes with `evaluate`/`observe`.

## Execution Strategy

- **Highly parallel.** Split work into independent modules that share neither a file nor a resource, and run modules that share nothing at the same time. Prefer many focused agents over a single serial agent.
- **Use vibe sessions.** In this harness that means `good` for design, debugging and multi-file work, and `fast` for mechanical work. `fast` is currently unusable because its model is end-of-life, so use `good` instead.
- **Serialize anything that shares a resource.** The shared resources here are the dedicated Chrome (`src/.tmp-jev-chrome`, `extension/dist-e2e`) and `extension/dist`. Only one agent may run a Chrome-based end-to-end script at a time; the family is `scripts/ocr_e2e.py`, `scripts/extension_e2e.py` and `scripts/extension_batch.py`, sharing `scripts/_cdp.py` as their CDP client, and `scripts/scan_e2e.py` belongs to that same family. `scripts/demo_e2e.py` belongs to it too even though it drives the *demo's* Chrome (port 9355): it must not run while the demo, the CLI or another member is running. No agent may call `free_profile()` on its own or kill a Chrome it did not start; only a Chrome end-to-end script of that family may clear the profile (at its own startup, and only while no other agent is using the dedicated Chrome), and two agents must never edit the same file.
- **Keep going** until every executable task in the plan is done or a real block is hit. Before reporting a block, exhaust the available tools and data; one failed check is not a block.
- **Verify each finished module immediately** with the check that belongs to it: `node --test "extension/test/*.test.mjs"`, `uv run pytest`, `uv run ruff check .`, `uv run python extension/build.py`, and — for anything that changes the screenshot reader's accuracy — the live `uv run --group e2e python scripts/ocr_e2e.py` with both gate groups matching. The strategy's server-stack rule maps onto the dedicated-Chrome serialization above, and this repository has no `lunia_ops.py`, `golden 11/11`, `e2e_warm.py` or `loadtest.py`.
- **Things only the user can do** (acting inside the game, pressing UAC, deciding a switch): stop and give step-by-step instructions; never assume it is already done.
- **Anything that can be done on the user's behalf: just do it.**
