# 計劃：三層找商品（查表 → 搜尋 → 底材）

狀態：**已完成並定版。** 第三層後來改成「程式先比對底材、比對不到才由 Jev 挑」，實際行為見 `AGENTS.md`。

## 一、為什麼要做

有些裝備在現在的流程裡查不到。現在的流程只有一條路：Jev 在搜尋欄輸入名字，再從結果挑商品。

已經看到的失敗：
- 輸入 `Rare Ring`、`Magic Grand Charm`、`White Archon Plate`，Traderie 回「No results could be found」。原因是 Traderie 的目錄裡只有底商品（Ring、Grand Charm、Archon Plate），品質字（Rare、Magic、White）不是商品名稱。
- 輸入 `Small Charm` 時，結果頁明明有這個商品，Jev 卻回「無法繼續」，整趟停止（同一個名字後來另一次又跑得通）。
- 商品網址和名字不一定一樣，例如 `Stone of Jordan` 的網址是 `the-stone-of-jordan`。

## 二、你已經決定的事

| 問題 | 你的決定 |
|---|---|
| 圖片辨識（OCR） | 這一輪不做。輸入只收文字（英文或中文）。 |
| 中英文對照表 | 資料來源用 https://d2r.world/zh-TW |
| 第一層「程式直接決定商品網址」會違反現有規則 | 修改規則，照你的設計做 |
| 底材小表放什麼 | 用 https://d2r.world/zh-TW 的「基礎裝備」整理 |

## 三、流程

```
輸入的名字（英文或中文）
   │  先整理：多餘空白、大小寫、全形字、中文轉英文
   ▼
第一層  查表直接跳     查得到 → 直接開商品頁 → 檢查頁面對不對 ──對──→ 完成
   │ 查不到，或開了之後頁面不對
   ▼
第二層  Jev 搜尋       Jev 在搜尋欄輸入「整理後的英文名」，看結果
   │ 結果有商品 → 進商品頁 → 完成
   │ 結果是「沒有找到」
   │   先檢查：名字有沒有打錯（空白、符號）？是不是新物品（兩張表都沒有）？
   ▼
第三層  底材小表       只在「名字格式沒問題、但真的沒結果」時才用
       Jev 從固定清單選一個底材，或選「以上都不是」
       選到 → 用底材英文名搜一次 → 進商品頁 → 完成（畫面註明：顯示的是底材，沒有依品質篩選）
       沒選到 → 顯示「找不到這個裝備」→ 結束，不再猜
```

幾條原則：
- 每一層只試一次，第三層重搜也只一次，不會無限重試。
- 第二層裡 Jev 只負責「輸入」和「看結果」，輸入的字是程式給的，Jev 不會自己改關鍵字。
- 第一層直接開商品頁後，程式一定會檢查頁面標題是不是你要的商品；不對就退回第二層。表格可能過期，不能無條件相信。
- 「找商品」這一步第一層不花 Jev 的呼叫。但開了商品頁之後，讀掛單和讀成交仍然會問 Jev（現有做法，這次不改）。

## 四、會完成的功能與測試方法

「怎麼測」都是你在側邊欄裡操作的步驟。我會先自己跑過一遍，確認過才請你測。

### 功能 1：整理輸入
把你輸入的名字整理好：去掉多餘空白、統一大小寫、全形變半形、中文名換成英文名。
- 怎麼測：
  1. 輸入 `  harlequin   CREST `（前後和中間多空白、大小寫亂），按「開始查詢」。
  2. 應該跟輸入 `Harlequin Crest` 的結果一樣。
  3. 輸入中文名（例如「哈勒昆之冠」，這個中文名要等表做好後以表裡實際收錄的為準），應該查到同一個商品。

### 功能 2：對照表產生工具
由我寫一支工具，自動從網站抓出三份表，不用手寫：
- 表 A：Traderie 商品「英文名 → 商品網址」（從 Traderie 自己的商品清單抓）。
- 表 B：「中文名 → 英文名」（從 d2r.world 抓）。
- 表 C：底材清單（從 Traderie「base」分類抓，再用 d2r.world 補中文名。這樣清單裡每一個底材在 Traderie 一定查得到）。
工具跑完會產出一份「對不上的名單」，例如兩邊名字不同的項目，由你看過再決定怎麼處理。
- 怎麼測：我跑完後給你一份報告，內容是各表有幾筆、對不上的有幾筆、前 20 筆對不上的是什麼。你只要看數字合不合理（Traderie 的 uniques 大約幾百項）。你不用跑工具。
- 風險：Traderie 有防機器人驗證，一般下載會被擋（我試過，回 403）。工具要用真的 Chrome 去開。若跑到一半要你按「我不是機器人」，我會停下來告訴你怎麼按。d2r.world 的資料是在瀏覽器裡才解開的，也要用同樣方式讀。

### 功能 3：第一層，查表直接跳
名字在表 A 查得到，就直接開那個商品頁，不經過搜尋。
- 怎麼測：
  1. 輸入 `Stone of Jordan`（網址和名字不同的例子）。側邊欄應該很快開到商品頁，不用經過搜尋。
  2. 結果頁會多一行「查詢方式：查表」。
  3. 對比：同一個名字在現在的版本要多花幾步搜尋。

### 功能 4：第一層的檢查與退回
直接開商品頁後，檢查頁面是不是你要的商品；不是（例如表過期、網址已改）就自動退回第二層。
- 怎麼測：我會故意放一筆錯的對照（網址指向別的商品），確認它退回搜尋、最後仍然查對。你的操作：看結果頁「查詢方式」那行是不是寫「查表失敗，改用搜尋」。

### 功能 5：第二層，搜尋，加「打錯字」檢查
沿用現在的搜尋流程。搜尋沒結果時，先檢查名字有沒有明顯問題：
- 空白不對、有奇怪符號 → 整理後重搜一次。
- 兩張表都查不到 → 提示「可能是新物品，表還沒更新」。
- 怎麼測：
  1. 輸入 `Harlequin Crest`（正常）→ 不應出現任何提示。
  2. 輸入一個完全亂打的字（例如 `Zzzz Qqqq`）→ 應看到「找不到這個裝備」，且提示「可能是新物品或名字打錯」。

### 功能 6：第三層，底材小表
第二層「格式正確但沒有結果」時，Jev 從底材清單選一個底材或選「以上都不是」。選到就用底材英文名搜一次。
- 怎麼測：
  1. 輸入 `Rare Ring`。應該查到 Ring 的商品頁，畫面註明「你查的是 Rare Ring，顯示的是 Ring，沒有依品質篩選」。
  2. 輸入 `Magic Grand Charm`、`White Archon Plate`，同樣檢查。
  3. 輸入亂打的字（同功能 5）→ 應該走到「找不到這個裝備」，而不是亂猜一個底材。
- 需要你做的事：這一層要讓 Jev 讀一份清單，我估計要修改 `services/`（後端），並且重新部署到 Vercel。部署需要你的帳號，到時我會用逐步說明告訴你每一步。在你部署以前，我會在自己電腦上用本機後端測給你看。

### 功能 7：結果頁標示
結果頁顯示這次是怎麼找到的：「查表」、「搜尋」、「底材（顯示的是 xxx）」，以及找不到時的原因。
- 怎麼測：上面各功能的步驟裡會看到；另外三種各跑一次，確認文字不會混在一起。

### 功能 8：規則與說明文件
修改 `AGENTS.md`、`README.md`、`docs/design.md`、`extension/README.md`：
- 允許第一層用對照表直接跳。
- 底材小表是固定清單，只在第三層使用，說明與「不得用網站詞彙過濾元素」的規則不衝突的理由（它不過濾頁面元素，只是給 Jev 一份選項）。
- 怎麼更新三份表。
- 怎麼測：你不用測，我會在最後給你重點。

### 功能 9：自動測試與實機驗證（我做）
- 離線測試（不花錢、不連網）：整理輸入、查表命中與落空、第一層頁面不對時退回、第二層檢查、第三層選到與選不到。
- 實機：在側邊欄各跑功能 3、4、5、6 的例子，每個至少一次，並截圖給你。

## 六、這份計劃不包含的東西

- 圖片辨識（你已決定這一輪不做）。
- 先前提出的其他備案：商品真的沒有資料時不要判失敗、筆數不一致時重讀、Jev 誤判無法繼續時重問、商品比對收緊。這些跟找商品是兩件事，這份計劃不含，要不要做請另外告訴我。

## 七、我確認過、你可能想知道的事實

- Traderie 商品頁標題下面有自己的分類（例如 `Small Charm / Charms / Charm`），可以拿來當第一層的額外檢查。
- 之前的紀錄裡，一般名稱（Harlequin Crest、Stone of Jordan、Archon Plate、Grand Charm、Jewel、Ring）都查得到並通過檢查；失敗的是帶品質字的名稱和一次 Jev 誤判。
- 表是某個時間點的拷貝：遊戲或網站新增物品後會慢慢過期。過期的後果只是退回第二層，比現在慢一點，不會查錯。
